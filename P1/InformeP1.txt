Introduccion: 
    - En esta práctica, mediremos mediante tres algoritmos de cálculo del termino n-ésimo de Fibonacci.
        - El primer algoritmo es recursivo, con complejidad O(φ^n) donde φ = (1+√5)/2
        - El segundo algoritmo es iterativo, 0(n)
        - El tercer algoritmo está basado en "fast doubling", 0(log n)
Los tamaños de entada varian segun el algoritmo, dado que sus complejidades son muy distintas entre si: valores pequeños
para el algoritmo recursivo y valores en progresión geométrica de razón diez para los algoritmos iterativo y de fast
doubling.

    - Para medir tiempos pequeños de manera precisa utilizamos el umbral de confianza de 500 µs. En caso de la que 
    la medición de X vector sea menor al umbral, es repetida 1000 veces para minimizar los posibles errores,

    - En la tabla, los tiempos a los que se les realizó este proceso aparecen junto a un (*). Esa marca se determina

Conclusiones: *mejorar conclusiones con los datos actualizados*
    - Debido a que el algoritmo empleado en Fibonacci V1 tiene una complejidad de O(φ^n), sus tiempos de ejecución crecen de forma
    explosiva incluso para valores de n muy pequeños (ya en n = 32 se alcanzan 32378 µs, frente a los 0.018000 µs de n = 2), lo que
    hace inviable emplearlo con valores de n grandes.
    - El algoritmo de Fibonacci V2, de complejidad 0(n), presenta un crecimiento mucho más contenido: incluso para n = 100000000, 
    el tiempo de ejecución es de aproximadamente 378027 µs, un valor manejable en comparación con el crecimiento exponencial de V1.
    - Por último, el algoritmo de Fibonacci V3, basado en la técnica de 'fast doubling' y con complejidad 0(log n), es notablemente
    el más eficiente de los tres: para n = 1000000000 aprenas requiere 0.246000 µs, un tiempo practicamente constante en comparación
    con el crecimiento de los otros dos algoritmos.
Se confirma empíricamente que reducir la complejidad supone una mejora de eficiencia radical, especialmente relevante cuando se 
trabaja con valores de n muy grandes.
